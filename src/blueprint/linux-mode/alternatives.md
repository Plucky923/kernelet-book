# Alternatives considered

*The designs that lost, one paragraph each, with the reason. The reason is what stops the next reader from trying them again. Numbers marked* measured *come from the experiments listed on the [prototype page](prototype.md#earlier).*

## For reaching the kernelet from a system call

**No patch: Syscall User Dispatch.** Linux can turn a task's system calls into a signal, which a stub in the process could forward to the endovisor. *Measured*: at least 885 ns added per call, against nothing measurable for the gate. More important, Linux clears the setting at every `fork` and `exec`, so only a sandbox's first thread would ever be intercepted; the tenant can also jump into the stub's exempt range, or flip the selector byte, and call Linux directly. Linux's own documentation says it is not a security mechanism. Rejected: without a patch the kernelet is not the tenant's boundary.

**No patch: seccomp user notification, or ptrace.** Both put the answer in another process, so each call costs two context switches. *Measured on the development machine*: 5.7 µs and 8.2 µs per call, against 1.9 µs for dispatch on the same machine. Rejected on cost.

**A hook in the architecture's entry code.** The first patch hooked x86-64's `syscall` path. A kernel built with 32-bit compatibility has three more entry instructions, each a complete escape. Replaced by the gate in the generic entry layer, which every entry passes through.

**Servicing calls on a separate kernel thread.** Park the tenant's task and hand the call to a kernel thread per virtual CPU, which can be stopped cooperatively. *Estimated* at 1.5 to 3 µs per call for the handoff, and the servicing thread that loops is no more killable than the tenant's task was. Rejected.

## For tenant memory {#memory}

**Linux owns the address space; the kernelet keeps a side table.** The first design let Linux's address space be the truth and had vOSTD record, for each frame it supplied, the tenant address it was mapped at, so that copies could go through the frame's kernel alias. Linux tears mappings down without telling the supplier, so an entry could outlive its mapping and then *resolve*, silently, to a frame that might by then belong to another tenant. Keeping it coherent needs Linux's MMU-notifier protocol, a kernel build option, and a non-sleeping lock on every copy. Replaced by the model below, which has no second structure to go stale, and that in turn by the [`VmSpace` over Linux's own page table](virtualizing-ostd/memory.md#space), which has none either: what a kernelet maps there are raw frame numbers, which Linux never tears down or moves on its own (host property P1).

**The kernelet's page table as the model, and Linux's as a cache of it.** The design this chapter carried before the `VmSpace` over Linux's address space ([register D95](../../notes/design-register.md#decisions), superseded by D125) kept OSTD's page-table code verbatim. The kernel proper's page tables lived in frames of the grant, written only by the kernelet and never walked by the processor; Linux's page table for each was a cache of it, filled on demand by an endovisor fault handler that walked the model itself and checked every frame against the grant, and emptied by a `tlb_shootdown` service that removed cached translations with `unmap_mapping_range()` on a file per model; fills and flushes were interlocked by a per-model reader-writer semaphore, and vOSTD freed nothing an unmap removed until the flush had returned (D111). Once a page was cached the steady state was native: one level of page table, no second walk, no exit. What it cost was first touch and every protection change, paid in faults rather than in writes, which is the wrong currency for work that forks, maps and exits constantly, the shells, build systems and agents this book is for. Every page the kernel proper mapped without a tenant fault cost one Linux fault at its first touch, about a microsecond (*estimated*; **[unverified]**), that a container does not pay, and the kernel proper maps ahead more than it seems: its page-fault handler maps up to sixteen pages around the faulting one for ELF segments, `fork` maps every page of the parent into the child, and `mremap` remaps page by page, so under the cache fault-around, which exists to save faults, saved none. A write-protect was an eviction: `protect` became a `tlb_shootdown`, so after a `fork` or an `mprotect` even reads faulted again to refill, where native Linux narrows the entry in place and only writes fault. A demand-paged fault took a detour through Linux's fault path, the resume hook, the kernel proper's handler and a refill. And two tables were kept coherent by a lock and a rule that the prototype never raced. The objection on which it was chosen, that a kernelet-side record of Linux's address space goes stale, as the side table above did, does not hold for a raw-frame-number area, which Linux never touches on its own initiative ([Memory](virtualizing-ostd/memory.md#host), P1); and a vOSTD bug still cannot map a frame outside the grant, since the endovisor checks every frame in `vm_map`.

Two findings against it as built stand as well, both found in review of its replacement and both shared by any design that kept its shape. Each model's file came from `anon_inode_getfile()`, which hands every caller the one shared anonymous inode, so the flush through one model's file reached every model's area at the same addresses, and every other mapping of an anonymous inode in the guest at an overlapping offset; with one model per test it went unnoticed. And each model's Linux address space, made with `mm_alloc()` on the carrier that registered the model, kept that carrier as its owner, without a reference, so once that carrier died while its siblings faulted, every fault in the space read a freed task. The design that replaced it gives each space's file an inode of its own and makes the root carrier the owner ([Memory](virtualizing-ostd/memory.md#space)).

**Bracketing accesses with the processor's user-access flag.** A kernelet runs in kernel mode and can set the flag itself. *Measured*: that works for a good address, and takes the task down for a bad one, because Linux will not find a recovery entry for an instruction in a kernelet. The kernel proper validates pointers by faulting on them, so this cannot deliver its contract.

**The supervisor alias.** Map the model's upper-level entries a second time in the kernel half of the carrier's address space, with the user bit cleared, so that a tenant address plus a constant is a kernel address and a copy needs no software walk. It was adopted on paper with one gate: its cost in TLB entries had to be measured. *Measured in a model*: for a 16-byte copy it saves about 7 ns over the walk when the working set is small and nothing when it is large, where its extra TLB misses cost as much as the walk does ([the table](virtualizing-ostd/memory.md#copies)). Against a saving that small stand real costs: it writes page-table entries Linux believes it owns, in a slot of the address-space layout that nothing reserves; it must be reinstalled in every new address space; and it opens a kernel-mode window onto user pages, which is what SMAP exists to prevent. Rejected.

**Ordinary pages instead of raw frame numbers.** Inserting tenant pages as normal, reference-counted pages would let Linux subsystems pin them, and a pin is a reference that can outlive the kernelet's own idea of who owns the frame, up to and past the day the grant is returned. No tenant operation needs pinning, since a tenant never calls Linux. Raw frame numbers give the right contract: Linux maps what it is told and keeps no claim of its own.

## For tasks

**Letting Linux service the tenant's own `clone`.** Decline the call at the gate, let Linux create the child, and have the kernelet do its bookkeeping on both sides. It is the cheapest way to get a thread that shares its parent's Linux address space. It was dropped because the kernel proper would have to know that its `clone` is being serviced elsewhere, and the design's central claim is that the kernel proper's source does not change. What the kernel proper actually does is create an OSTD task, and vOSTD has to honor that.

**A Linux task for every kernelet task.** Make each task the kernel proper creates a Linux task of its own, a child of the root carrier, and let Linux schedule them all; a virtual CPU is then only a lease on a copy of the per-CPU data. It is the most direct mapping, it needs neither the address-space helper nor the floating-point services, and the first three prototype phases were built this way. It loses on three counts. The kernel proper's scheduler is inert: Linux decides which tenant thread runs, by Linux's policy, and the tenant's priorities, real-time classes and affinities mean nothing. A sandbox costs Linux a task structure, a kernel stack and a process identifier per tenant thread, so a tenant's thread count is a host resource. And the threads of one tenant process are separate Linux processes with separate page tables, since OSTD does not say at task creation which address space a task will use, so every first touch and every flush is paid once per thread. The [adopted design](virtualizing-ostd/tasks.md) removes all three.

**Kernel threads as carriers.** They cannot enter user mode.

**Linux's user-mode-helper interface.** It creates a task that can enter user mode with no new export. But every such task starts as a child of a kernel worker, in the root control group, with root's credentials and no seccomp filter, and each of those would have to be repaired by hand on a path where a mistake is an escape. Cloning the root carrier inherits all of them.

**Swapping floating-point state with Linux's helper for guests.** When a carrier changes tenant threads, the floating-point registers must change with it. Linux has an exported function that swaps a task's whole floating-point context for another, written for KVM's guests; it exists only in kernels built with virtualization support, and it swaps Linux-format contexts that the endovisor would have to allocate per tenant thread. The design instead [saves and loads](virtualizing-ostd/user-mode.md#fpu) the user-visible state into the buffer OSTD already keeps per thread, which needs nothing that is not exported everywhere.

## For scheduling {#scheduling}

The [Scheduling](virtualizing-ostd/scheduling.md) page sets four tests (exact, efficient, fair, cooperative) and compares six designs in one table. These are the five that lost.

**Hints: translate the kernelet's decisions into Linux's own knobs.** Keep a Linux task per kernelet task and have a service set its `nice` value, its affinity, or a real-time class from what the kernel proper's scheduler wants. It asks nothing of Linux. It is not exact: Linux's fair class treats a weight as a share and not as an order, so "run A before B" cannot be said, and any policy Linux lacks cannot be said at all. And the one knob that does give an order, a real-time class, is a way out of the sandbox's share: real-time tasks run before every fair task on the machine, the group cap notwithstanding unless the operator has also configured real-time group scheduling, so a tenant's priorities would become the neighbors' latency.

**Gating: a Linux task per kernelet task, of which only the chosen are awake.** Let the kernelet's scheduler run as it would on a machine, and make every task it has *not* picked sleep in Linux, so that Linux never has more runnable tasks of a sandbox than virtual CPUs and its choice is forced. This is exact and fair, and needs nothing from Linux. It is slow in the one place that matters: every switch between kernelet tasks is a Linux wake-up of one task and a Linux sleep of another, through both schedulers and usually a cross-processor interrupt, a few microseconds (*estimated*) where a switch inside the kernelet costs what a function call and a register save cost. It also keeps the cost in Linux tasks and page tables of the design above it.

**A BPF scheduler, `sched_ext`.** Since v6.12 Linux has a scheduling class whose decisions are made by a loaded BPF program, and which by default takes over every task of the fair class ([`ext.c`](https://elixir.bootlin.com/linux/v6.12/source/kernel/sched/ext.c#L3966)); a kernelet could publish its choices in a BPF map for such a program to follow. This was the most tempting idea and fails on ownership, not on mechanism. A machine has *one* BPF scheduler at a time, for every task on it, so the operator's machine-wide scheduler would have to be the kernelets' scheduler; the host's own processes, and the group weights and caps that make sandboxes fair to one another, are no longer enforced by Linux's fair class but by whatever that program reimplements; and a program that misbehaves is ejected by Linux for the whole machine, tenants and host alike. It also needs a Linux built with BPF type information, which the chapter otherwise does not, and still pays a Linux switch per kernelet switch. A design in which a *tenant's* kernel supplies BPF programs to the host's scheduler fails sooner, on the threat model: the verifier guards memory safety, not fairness.

**A hook in the scheduler's core.** Patch `__schedule()` so that, for a sandbox's group, it asks the kernelet which task to pick. Exact and efficient, and unacceptable: the kernelet's policy code would run under Linux's run-queue lock with interrupts off, where it cannot be evicted, charged or bounded; and the patch would sit in the most performance-sensitive and most frequently rewritten function in the kernel. The gate's two hunks are in code that changes rarely; this one would not survive a release.

**Gang scheduling.** Run all the virtual CPUs of a sandbox at the same instants, as some hypervisors do, so that a lock holder is never descheduled while a sibling spins on the lock. Linux has no such class (its core scheduling, [`SCHED_CORE`](https://elixir.bootlin.com/linux/v6.12/source/kernel/Kconfig.preempt#L118), co-schedules hyperthread siblings for a different purpose), so it would be a new scheduling class, and it wastes processors whenever a sandbox's virtual CPUs are not equally busy. The design gets the benefit it was after, that a virtual CPU is not descheduled while it holds a lock, from the [mirrored preemption count](virtualizing-ostd/scheduling.md#cooperative), for the price of one increment.

## For containment

**Revoking a kernelet's text.** To stop a carrier that will not leave kernelet code, unmap that kernelet's text and flush every processor's TLB, so that the carrier faults at its next instruction and the die notifier catches it. The range flush is not exported, so this costs a machine-wide full flush per termination, and it turns every forced termination into a printed oops. Replaced by [eviction](faults-and-reclamation.md#eviction), which needs neither.

**Catching tenant exceptions with a signal handler inside the tenant.** Costs no patch lines. Linux then writes a signal frame onto the tenant's stack, which the tenant controls and may have made unwritable, and a trusted trampoline has to live in the tenant's address space. Replaced by the gate's resume hook.

## For the whole mode

**Each instance as a Linux module.** No loader to write and no exports to ask for. Linux's module area is about 1 GiB and every instance would need its own copy of the text: tens of sandboxes per machine.

**Each kernelet in a hardware-virtualized guest, in kernel mode of that guest.** This restores everything: hardware separation, forced termination, exact accounting. It also needs a hypervisor, gives up running in the host's kernel mode, and adds a second level of address translation to every tenant memory access, *measured* at a factor of 1.20 on a realistic working set. That is a virtual machine, and the book is about the alternative to one.
