# API virtualization, in one page

**The precondition.** A *framekernel* splits a kernel into a privileged framework that owns every sensitive resource and encapsulates every `unsafe` block, and services written in safe Rust against the framework's API. In Asterinas the framework is OSTD, about 45,600 lines, of which about 6,000 are verified in a separate effort; the services above it are about 183,000 lines and contain no `unsafe` block (measured on the tree). OSTD's API is built so that a safe caller cannot cause undefined behavior: user memory and device memory are *untyped*, reachable only through copying readers and writers; page tables are driven through a *cursor*, a locked walk over the caller's own address space that cannot map the kernel half; device registers, interrupt lines and DMA are reached through handles. The property this book rests on is that the API is the services' entire authority. Everything the kernel above OSTD can do to the machine, it does by calling a name OSTD exports.

**The move.** If a kernel's services reach the machine only through the framework's API, then a tenant's own instance of that kernel needs only an implementation of the API whose global effects are confined to the instance. The implementation is built from OSTD itself: OSTD is compiled a second time under a `kernelet` build configuration, a Cargo feature of the `ostd` crate, and the kernel is compiled, unmodified, against that build. Under the configuration, every public item of OSTD is one of three things.

- **Identical.** An operation whose effect is local to the caller keeps its implementation: user-memory copies, spin locks, the clock, the page-table cursor over the caller's own address space, the value types for CPU context and exceptions.
- **Virtualized.** An operation that touches machine-wide state keeps its name and signature and gets a per-instance implementation over the endovisor: task creation and waiting, device registers and interrupt lines, DMA, frame allocation, timers, logging, the view of how many CPUs and how much memory exist.
- **Absent.** An operation a tenant must never have is not defined: interrupt masking, inter-processor interrupts, the kernel page table, per-CPU variables, the raw frame allocator, machine halt. Reaching for one is a compile error, not a run-time check.

Of the kernel's 685 references to OSTD at commit `ab9a4cfdc`, roughly 230 are identical, 150 virtualized and 300 absent, the last almost entirely in driver and machine-wide code that moves to the host (counted by grep, upper bounds). The classification and the adaptations that make OSTD's API virtualizable, since it was not designed to be, are a chapter of their own, the OSTD API taxonomy.

Which of the three an item is can be read from OSTD's own source, so the virtualized API cannot drift from the API it virtualizes; and the kernelet build of OSTD may use `unsafe` where OSTD does, so the virtualized implementation is not limited to what safe Rust can express. Only the kernel proper is held to `forbid(unsafe_code)`.

**The kernelet.** The result is a *kernelet*: one instance of the Asterinas kernel serving one tenant's processes, in kernel mode, in the same boot image as every other kernelet and the host kernel, with its own copy of the kernel's writable state and its own heap, mapped only by its own page tables. The kernel proper and its OSTD build are linked into an ELF of their own, the *kernelet image*, separate from the host kernel's ELF; the two are produced by one build and combined into one boot image, and nothing is loaded from outside the image at run time. The kernelet image has no undefined symbols: its single entry point receives a table of `extern "C"` function pointers, the *endovisor ABI*, through which every virtualized operation reaches the host kernel, and returns a table of the kernelet's own entry points. What sits beneath the ABI is the *host kernel*: the same kernel source built against OSTD's host build, which boots the machine and runs the host user space. Inside the host kernel, the *endovisor* implements the ABI and creates, schedules, mediates and destroys kernelets. Where a hypervisor sits *beneath* its guests in hardware, the endovisor sits *inside* the host kernel and *beside* the kernelets, at the same privilege level, and a crossing into it is an indirect call through the table, on the caller's stack. The name is chosen for that fact.

| | Machine virtualization | OS virtualization | API virtualization |
|---|---|---|---|
| Reach decided by | hardware | bookkeeping | names and imports |
| Access checked by | hardware | permissions | handle and owner |
| A crossing is | a VM exit | a system call | a function call |
| Kernels per tenant | one each | shared | one instance each, one boot image |
| The kernel's globals | duplicated | partitioned | one text, per-instance data |
| The host's globals | hidden | shared | unnameable |
| Schedulers | two, stacked | one | two levels, one decision each |
| Kill and reclaim | destroy the VM | tear down the views | unmap and release |

**Three lines, not one.** The boundary is not drawn by the compiler alone, and this book does not claim it is. *Names and imports* decide what a kernelet can reach: the kernel proper can name only what the kernelet build of OSTD defines, and the kernelet image can import nothing, since it has no undefined symbols and reaches the host only through the ABI table it is handed at entry; an audit of the kernelet image's symbol table after every build confirms both. *Run-time checks* decide what a kernelet may touch: everything it holds across the boundary is a typed, unforgeable handle into its own table, resolved on every use against a per-kernelet epoch that one store bumps to revoke everything; and every frame carries an owner tag that device backends and the allocators check before touching it. *Page tables* make a kernelet's state private and turn a class of host bugs into faults: two windows in the kernel half of the address space, one for the kernelet image's writable sections and one for its heap, are mapped only by that kernelet's page tables, so a pointer into a kernelet's memory dereferenced by the host acting for someone else faults instead of reading. The page tables are a backstop for the language boundary, not a second layer of address translation; there is no nested paging and no trap.

**Three obligations.** A kernelet is worth having only if it is cheap, if a misbehaving one can be contained, and if a dead one can be reclaimed. Each obligation has one answer here, and the design chapter builds each answer in full. *Every kernelet needs its own state*: the kernel proper holds 96 statics of per-tenant state (counted on the tree), and rewriting each into a field threaded through every call touches some 700 functions (a call-graph estimate); the kernelet image's writable sections are linked at one fixed address, and the windows give each kernelet its own copy there, so the statics keep their names and their addresses and no source changes. *The host must retain no reference into a kernelet*, or killing it leaves dangling references and reclaiming it hands the next tenant frames the host still points at; the endovisor remembers kernelets by *names*, integers meaningful only to the kernelet that minted them, and a sealed type bound is the only thing a host table may store about a kernelet. *Misbehavior must end one kernelet*: a panic, an unmet allocation, a spin with preemption disabled, or an operator's kill ends the kernelet at its next quiescent point, where it holds no host lock, by abandoning its stacks rather than unwinding them, and reclamation drains every host structure that names the kernelet, unmaps its windows, forgets its heap and releases its frames, running none of the kernelet's destructors.

**What is new.** Language-based isolation from SPIN through Singularity and RedLeaf built most of these pieces for components inside one system, and rump kernels compiled an unmodified kernel against a facade for portability; Related Work in The Paper credits both. What is new is the setting and four things it forced. The cut is made at a framework's API, so the tenant's kernel is a complete Linux-compatible kernel, not a component. The virtualized API is OSTD's own source under a build configuration, and the boundary is one table of C-ABI functions checked against the kernelet image's symbol table, not a rewritten kernel. Per-instance windows in one ring-0 boot image spare the kernel's globals a rewrite. And two kinds of lock, host and kernelet, make killing an adversarial instance sound. On the axis of reach and access, API virtualization sits between the two incumbents; on containment of the host and on side channels it sits below a microVM, and the Limitations chapter will say so.
