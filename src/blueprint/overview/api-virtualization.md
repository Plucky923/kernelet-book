# API virtualization, in one page

**The precondition.** A *framekernel* splits a kernel into a privileged framework that owns every sensitive resource and encapsulates every `unsafe` block, and services written in safe Rust against the framework's API. In Asterinas the framework is OSTD, about 20,000 lines in an x86-64 build, of which about 6,000 are verified in a separate effort; the services above it are about 135,000 lines, contain no `unsafe` block, and are growing fast as file systems, socket types and device drivers are added to them (measured on the tree at commit `0c6053709`, as [the inventory](../../notes/ostd-api-inventory.md#sizes-as-built) counts them). OSTD's API is built so that a safe caller cannot cause undefined behavior: user memory and device memory are *untyped*, reachable only through copying readers and writers; page tables are driven through a *cursor*, a locked walk over the caller's own address space that cannot map the kernel half; device registers, interrupt lines and DMA are reached through handles. The property this book rests on is that the API is the services' entire authority. Everything the kernel above OSTD can do to the machine, it does by calling a name OSTD exports.

**The move.** If a kernel's services reach the machine only through the framework's API, then a tenant's own instance of that kernel needs only an implementation of the API whose global effects are confined to the instance. The implementation is built from OSTD itself: OSTD is compiled a second time under a `kernelet` build configuration, a Cargo feature of the `ostd` crate, and the kernel is compiled, unmodified, against that build. Under the configuration, every public item of OSTD is one of three things.

- **Identical.** An operation whose effect is local to the caller keeps its implementation: user-memory copies, spin locks, the clock, the page-table cursor over the caller's own address space, the value types for CPU context and exceptions.
- **Virtualized.** An operation that touches machine-wide state keeps its name and signature and gets a per-instance implementation over the endovisor: task creation and waiting, device registers and interrupt lines, DMA, frame allocation, timers, logging, the view of how many CPUs and how much memory exist.
- **Absent.** An operation a tenant must never have is not defined: interrupt masking, inter-processor interrupts, the kernel page table, per-CPU variables, the raw frame allocator, machine halt. Reaching for one is a compile error, not a run-time check.

Of the kernel's 685 references to OSTD at commit `ab9a4cfdc`, roughly 230 are identical, 150 virtualized and 300 absent, the last almost entirely in driver and machine-wide code that moves to the host (counted by grep, upper bounds). The classification and the adaptations that make OSTD's API virtualizable, since it was not designed to be, are a chapter of their own, the OSTD API taxonomy.

Which of the three an item is can be read from OSTD's own source, so the virtualized API cannot drift from the API it virtualizes; and the kernelet build of OSTD may use `unsafe` where OSTD does, so the virtualized implementation is not limited to what safe Rust can express. Only the [kernel proper](terminology.md), the kernel's code above OSTD less the drivers and machine-wide subsystems that move to the host, is held to `forbid(unsafe_code)`.

**The kernelet.** The result is a *kernelet*: one instance of the Asterinas kernel serving one tenant's processes, in kernel mode, in the same address space as every other kernelet and the host kernel, with its own copy of the kernel's writable state and its own heap. The *kernelet image* is the ELF into which the kernel proper and its OSTD build are linked, separate from the host kernel's ELF. How it reaches memory depends on the host, built into one boot image with the host kernel or registered with it at run time, but on either, one copy of its code serves every kernelet and each kernelet has private memory only for its writable data. The kernelet image has no undefined symbols: its single entry point receives a table of `extern "C"` function pointers, the *service table*, through which every virtualized operation reaches the host kernel, and returns a table of the kernelet's own entry points. What sits beneath the table is the *host kernel*, the kernel that boots the machine and runs the host user space: either Asterinas itself, the same kernel source built against OSTD's host build, or Linux. Inside the host kernel, the *endovisor* implements the table and creates, schedules, mediates and destroys kernelets. Where a hypervisor sits *beneath* its guests in hardware, the endovisor sits *inside* the host kernel and *beside* the kernelets, at the same privilege level, and a crossing into it is an indirect call through the table, on the caller's stack. The name is chosen for that fact.

| | Machine virtualization | OS virtualization | API virtualization |
|---|---|---|---|
| Reach decided by | hardware | bookkeeping | names and imports |
| Access checked by | hardware | permissions | handle and owner |
| A crossing is | a VM exit | a system call | a function call |
| Kernels per tenant | one each | shared | one instance each, inside the host kernel |
| The kernel's globals | duplicated | partitioned | one text, per-instance data |
| The host's globals | hidden | shared | unnameable |
| Schedulers | two, stacked | one | two levels, one decision each |
| Kill and reclaim | destroy the VM | tear down the views | unmap and release |

**What draws the boundary.** Not the compiler alone, and this book does not claim it does. Two mechanisms draw it, one at build time and one at run time, and what neither covers is trusted. *Names decide what a kernelet can reach*: the kernel proper, compiled with `unsafe` forbidden, can call only what the kernelet build of OSTD defines, and the kernelet image can call the host only through the service table; an audit of every build checks both. *The endovisor's checks decide what a kernelet may touch*: what crosses the table as arguments is integers, names and indices that the endovisor looks up among the calling kernelet's own objects, and physical addresses that it checks against the frames the kernelet owns. *The rest is trusted*: the kernelet build of OSTD may use `unsafe`, so a bug in it is a bug in the host kernel; and a kernelet's memory is ordinary kernel memory, private because no safe code is ever handed a reference to it, not because page tables hide it. Each host chapter states these as invariants and says which are checked ([Asterinas](../asterinas-mode/principles.md), [Linux](../linux-mode/principles.md)).

**Three obligations.** A kernelet is worth having only if it is cheap, if a misbehaving one can be contained, and if a dead one can be reclaimed. Each obligation has one answer here, and the design chapter builds each answer in full. *Every kernelet needs its own state*: the kernel proper holds 96 statics of per-tenant state (counted on the tree), and rewriting each into a field threaded through every call touches some 700 functions (a call-graph estimate); the kernelet image is position-independent, and each kernelet maps the one copy of its code followed by a private copy of its writable data, at the same distance in every kernelet, so the code's program-counter-relative references reach the running kernelet's own statics, which keep their names, and no source changes. *The host must retain no reference into a kernelet*, or killing it leaves dangling references and reclaiming it hands the next tenant frames the host still points at; the endovisor knows a kernelet only through integers, its identifier, the indices of its virtual CPUs and devices, and physical addresses it checks against the kernelet's frames, and the types of the host's tables admit no pointer into a kernelet. *Misbehavior must end one kernelet*: a panic, an unmet allocation, or an operator's kill ends the kernelet at its next quiescent point, where it holds no host lock, by abandoning its stacks rather than unwinding them, and reclamation drains every host structure that names the kernelet, unmaps its instance of the image, forgets its heap and releases its frames, running none of the kernelet's destructors.

**What is new.** Language-based isolation from SPIN through Singularity and RedLeaf built most of these pieces for components inside one system, and rump kernels compiled an unmodified kernel against a facade for portability; Related Work in The Paper credits both. What is new is the setting and four things it forced. The cut is made at a framework's API, so the tenant's kernel is a complete Linux-compatible kernel, not a component. The virtualized API is OSTD's own source under a build configuration, and the boundary is one table of C-ABI functions checked against the kernelet image's symbol table, not a rewritten kernel. Position-independent instances, one copy of the code and a private copy of the data each, in the host kernel's own address space, spare the kernel's globals a rewrite. And two kinds of lock, host and kernelet, make killing an adversarial instance sound. On the axis of reach and access, API virtualization sits between the two incumbents; on containment of the host and on side channels it sits below a microVM, and the Limitations chapter will say so.
