# Terminology

The terms below are used in exactly these senses throughout the book. Generic nouns are lowercase, as "hypervisor" and "container" are; capitals mark the brand, Asterinas Kernelets, and Rust identifiers.

A **kernelet** is one instance of the Asterinas kernel compiled against an OSTD-shaped API, serving the user-space processes of exactly one tenant, running in kernel mode, in the same image as every other kernelet. A kernelet together with the processes it serves is that tenant's **sandbox**, in the sense in which a virtual machine or a container is one. The **host kernel** is the first instance of the Asterinas kernel that boots the machine, runs init and the host user space; it is the same kernel source as kernelet built against OSTD itself. Inside the host kernel, the **endovisor** is the component that creates, schedules, destroys and mediates kernelets and implements the endovisor ABI through which a kernelet reaches it; where a hypervisor sits beneath its guests in hardware, the endovisor sits inside the host kernel and beside the kernelets, and its boundary is that ABI, with per-kernelet page tables as a backstop, not a second layer of address translation. Sandboxes are created and configured from host user space by a **kernelet runtime**, in the way a container runtime creates containers. Every tenant must trust the host kernel; the parts of it that a kernelet's execution actually enters, the endovisor, OSTD, the drivers and the allocators, are the trusted computing base this book measures. A tenant is assumed to be hostile: it runs arbitrary native code in user mode and, through the syscalls it makes, drives arbitrary paths in its kernelet, which is safe Rust but which the tenant is trying to turn against its neighbors.

Throughout this book **the host** means the host kernel, so host tasks, host locks and the host heap are the host kernel's; where the endovisor specifically is meant, it is named.

A few further terms are used with fixed meanings:

- **API virtualization** is the idea: giving each tenant its own instance of a kernel by virtualizing the API the kernel is written against, rather than the hardware beneath it (machine virtualization) or the kernel's bookkeeping above it (OS virtualization).
- A **framekernel** is a kernel whose `unsafe` code is confined to a small framework and whose remaining code is safe Rust written against that framework's API. **OSTD** is the framework of Asterinas.
- The **kernelet build of OSTD**, also called **vOSTD**, is the `ostd` crate compiled with its `kernelet` feature: the same source, under which each public item is *identical* to the host build's, *virtualized* over the image ABI, or *absent*. It may use `unsafe`; the kernel proper may not.
- The **kernelet image** is the ELF into which the kernel proper and the kernelet build of OSTD are linked; the **host image** is the host kernel's ELF. One build produces both and combines them into one **boot image**. The kernelet image has no undefined symbols.
- The **image ABI** is what crosses a kernelet image's edge: the **service table**, a set of `extern "C"` function pointers the host hands a kernelet at its entry point and through which every virtualized operation reaches the host kernel; the **entry table**, the few addresses the image publishes in return; and the pages the two sides share. The **endovisor ABI** is a different interface, one level out: the one the endovisor offers *host user space*, through which a kernelet runtime creates and configures sandboxes.
- A **carrier** is a task of the host kernel that carries one of a kernelet's **virtual CPUs**: what the host schedules, and what the kernelet runs its own tasks on. A kernelet has a fixed number of them, chosen when its sandbox is created.
- The **kernel proper** is the tenant-facing, Linux-ABI kernel code above OSTD, minus the drivers and the machine-wide subsystems that move to the host kernel. It is the code that becomes a kernelet, crate `aster-kernelet`.
- A **tenant** is the principal a sandbox serves and the adversary the boundary is designed against; a **crossing** is a call from kernelet code into a virtualized item of its OSTD build, and through the service table into the host.
- **Safety**, **fault containment** and **fairness** are the three isolation properties the boundary must provide, defined at the start of [the previous page](goals.md) and stated as numbered obligations on [the next](api-virtualization.md).
